## 8. Архитектура

### Микросервисы vs Монолит

Микросервисы:
+ Независимое масштабирование и деплой
+ Изоляция отказов, разные технологии
- Сетевые накладные расходы, сложность распределённых транзакций
- Сложная инфраструктура (service discovery, трейсинг, централизованное логирование)

Монолит:
+ Простота разработки, отладки, транзакционности
- Деплоится целиком при любом изменении
- Сложнее масштабировать отдельные части

### Архитектурные паттерны

- API Gateway: единая точка входа; auth, rate-limiting, роутинг.
- Circuit Breaker: перестать вызывать падающий сервис; fallback; восстановление после таймаута.
- Saga: распределённая транзакция через компенсирующие операции.
- CQRS: разделить модели чтения и записи.
- Event Sourcing: хранить состояние как последовательность событий.
